# 배흐름 워치 앱 — 1단계 시험 앱

갤럭시 워치(Wear OS 3 이상, 워치5 프로 포함)에서 **워치 내장 GPS와 나침반만으로** 배의 흐름을 재는 시험 앱입니다.
휴대폰 앱 없이 단독으로 동작하고, 화면에 보이는 값을 1초마다 CSV 파일로 기록합니다.

## 화면

맨 위 다이얼: 12시(흰 삼각형) = 내 정면, 빨간 점 = 북쪽, 노란 화살표 = 배가 밀려가는 방향.
손목을 들어 화면을 보면 워치의 12시 쪽이 내 정면을 향한다고 보고 계산합니다.

아래로 스크롤(베젤/화면 쓸기)하면 시험용 값이 나옵니다.

| 줄 | 뜻 | 볼 점 |
|---|---|---|
| GPS ±m · 위성 | 위치 오차, 사용 위성/보이는 위성 | ±10m 이하면 좋음 |
| GPS 순간속도 | GPS 칩이 직접 계산한 순간 속도·방향 | 흐름 값과 비교용 |
| 흐름 N초 | 60초 위치로 계산한 배 흐름 (웹앱과 같은 계산) | 신뢰도 "높음"이 유지되는지 |
| 정면 / 편차 | 내 정면 방위(진북), 현재 위치의 자북 편차 | |
| 기울기 · 방위오차 | 화면이 수평에서 기운 각도, 센서가 추정한 방위 오차 | 화면을 볼 때 기울기와 방위가 안정적인지 |
| 자기장 µT · 보정 | 자기장 세기(한국은 약 50µT), 나침반 보정 상태 | **전동릴 가까이에서 "간섭!"이 뜨는지** |
| 배터리 · 시간당 | 현재 %, 시작 10분 후부터 시간당 소모량 | 하루 낚시를 버틸지 |
| 기록 | CSV 행 수, 파일 이름 | |

"보정 필요(8자)"가 뜨면 손목으로 8자를 몇 번 그리세요.

**주의 (시험 단계 한계):** 앱이 화면에 떠 있어야 GPS가 계속 측정됩니다. 기본값으로 화면이 계속 켜져 있어 배터리 소모가 실제보다 큽니다. 시계 화면으로 나가면 측정이 멈추거나 느려집니다. 백그라운드 측정은 2단계에서 넣습니다.

## 워치에 설치하기 (PC에서 와이파이로)

1. **워치 개발자 모드 켜기**: 설정 → 워치 정보 → 소프트웨어 정보 → "소프트웨어 버전"을 7번 누르기
2. **무선 디버깅 켜기**: 설정 → 개발자 옵션 → "ADB 디버깅" 켜기 → "무선 디버깅" 켜기. 워치와 PC가 **같은 와이파이**에 있어야 합니다.
3. **페어링**: 무선 디버깅 → "새 기기 페어링"을 누르면 IP:포트와 6자리 코드가 나옵니다. PC에서:

```bash
"$LOCALAPPDATA/Android/Sdk/platform-tools/adb" pair 192.168.0.10:37000 123456
```

4. **연결**: 무선 디버깅 화면 위쪽에 나오는 IP:포트(페어링 포트와 다름)로:

```bash
"$LOCALAPPDATA/Android/Sdk/platform-tools/adb" connect 192.168.0.10:41000
```

5. **빌드·설치** (이 `watch` 폴더에서):

```bash
./gradlew installDebug
```

워치 앱 목록에 "배흐름 시험"이 생깁니다. 처음 실행할 때 위치 권한을 허용하세요.
Android Studio에서 이 `watch` 폴더를 열고 ▶ 실행해도 됩니다.

## 기록 파일 가져오기

워치에 연결된 상태에서:

```bash
"$LOCALAPPDATA/Android/Sdk/platform-tools/adb" shell run-as io.github.gnslno1.shipnavi ls files/logs
```

```bash
"$LOCALAPPDATA/Android/Sdk/platform-tools/adb" exec-out run-as io.github.gnslno1.shipnavi cat files/logs/log_20261023_040205.csv > log.csv
```

앱을 실행할 때마다 새 파일이 생기고, 10초마다 저장됩니다.

## 시험 때 해볼 것

**집에서 (오늘 밤)**: 워치를 베란다·창가처럼 하늘이 보이는 곳에 **30분 동안 움직이지 않게** 두고 앱을 켜두세요.
기록을 `python tools/analyze_watch_log.py 파일.csv`로 분석하면 이 워치의 GPS 노이즈를 재서
신뢰도 기준이 맞는지 알려주고, 배터리 소모량도 나옵니다 ([tools/README.md](../tools/README.md)).

**배에서**:

1. 포인트에서 배가 흐를 때 1~2시간 켜두고, 휴대폰 웹앱과 흐름 방향·속도가 비슷한지 비교
2. 손목을 들어 화면을 볼 때 "정면" 값이 실제 바라보는 방향과 맞는지 (보이는 섬·등대 등으로 확인)
3. 전동릴을 감을 때와 멈췄을 때 자기장 µT와 정면 값이 튀는지
4. 1시간에 배터리가 몇 % 닳는지

## 자동 테스트

```bash
./gradlew testDebugUnitTest
```

`DriftTest`가 흐름 계산을 확인합니다: 웹앱(`app.js`)과 같은 입력에 같은 결과, 측정 구간·GPS 튐·부정확한 위치 처리,
그리고 실제 GPS 같은 노이즈에서 "높음" 판정의 90% 이상이 ±15° 안인지와 정지 상태에서 "높음"이 안 나오는지.

## 구조

| 파일 | 내용 |
|---|---|
| `Drift.kt` | GPS 위치 → 흐름 속도·방향 계산 (웹앱 `app.js`와 같은 방식) |
| `SensorHub.kt` | 워치 GPS, 방위 센서, 자기장, 배터리 읽기와 CSV 기록 |
| `TestScreen.kt` | 둥근 화면 UI |
| `MainActivity.kt` | 권한 요청, 화면 켜짐 유지 |
